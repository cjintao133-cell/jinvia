# Star River · C Core（工作草稿 / WIP）

> 一个**纯 C 的微内核基座**：不寄生在任何运行时之上（不要 Go runtime、不要 JVM、不要解释器），
> 扔到哪台机器都能自己站起来。外来的任何东西（插件/工具/能力）进来，只能走宿主定的那道门、由宿主批、由宿主编排。

**为什么是 C：** 其他语言再方便，底下都踩着一个别人的地板（Go 要 runtime、Python 要解释器、Java 要 JVM）。C 没有地板，C 自己就是地板。要"无限制"，就要自己浇地板。

---

## 三根柱子（不可违反）

1. **核不依赖插件（依赖方向）。** 核心只提供机制（mechanism），不提供策略（policy）。记忆、情绪、协议适配、工具……全部在核外，作为可拔插的插件存在。核越小越纯越好。
2. **外来者必须走沙箱门。** 任何外来插件不得与核共享内存。入口只有两条：进程外（子进程 + JSON-RPC/管道）或 WASM 沙箱（WASI，能力受限）。宿主函数契约决定它「能做什么」，默认什么都不批。
3. **解放，而非占有。** Apache-2.0，宽松、可商用、可嵌入。核不吞用户的业务、不锁用户的数据、不用许可证绑架。别人拿它去造什么、怎么造、卖给谁，一概不干涉。核只保证站得稳、跑得动、进得来出得去。

> 一句话：**核只做地基，不做房东。**

## 核的边界（草案，待定稿）

核里只允许有这几样：

- **事件总线**（命令/查询直接调，状态变更走广播；有界缓冲、丢弃有计数）
- **插件注册表**（发现、加载、生命周期）
- **宿主函数契约**（插件能调核的**唯一**一组函数；这是整套东西的宪法核心）
- **WASM 宿主**（内嵌，比如 wasm3 / wasmtime C API；外来插件跑在沙箱里）
- **最小存储/时钟等底座原语**（不掺业务）

核里**不允许**出现：记忆曲线、情绪状态机、具体模型协议、业务逻辑——这些全是插件。

## 第一块砖

**先定「宿主函数契约」，再写一行 C。** 契约稳，C 才敢长；契约乱，C 越大越死。
（对应旧 Go 内核里的 `scripts/check-open-split.sh` 守卫，思想一致：把"谁不能依赖谁""谁能调什么"钉死。）
